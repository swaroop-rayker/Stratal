Gate 2, step 2 of 2

Built on the approved low-fi wireframe (SCR-08-lofi_v1.html, approved 2026-11-19) inside the SCR-01 shell, using only design system v1 tokens, components and patterns; no new icon. Every number is what POST /model-specs/validate returns for this data today: the CIFAR-10 split ds_f8e67211dd94 (3×32×32, 10 classes) and a CNN of two convolutions. Open as SCR-08_v1.html#light to start in light.

Decisions made in this step, for review
  • A node is a small card: its ID in mono, its type, its key fields; a footer with its output shape and parameter count. Locked ends are dashed with a lock. The selected node has the accent outline and its edges turn accent.
  • The canvas is the sunken surface with a dot grid, as React Flow draws it, with zoom and fit buttons in the corner. Edges are plain lines; a skip edge is a curve with its label, never a colour alone.
  • The inspector uses the schema-form pattern approved for SCR-14: the property name in mono, its type as a badge, the schema's description with range and default as helper text. An inferred size shows "inferred: 3" in the input, in italics, and can be typed over.
  • The memory estimate is one bar in three parts with a text key: weights (accent), gradients (info), optimizer state (muted). Each part also has its number in the key, so the colours carry no meaning alone.
  • Problems use the danger colour only on the node's border, a warning icon and the problem list; each problem's node ID is a link that selects it. The list sits above the summary while there are problems and is hidden when there are none.
  • Greyed palette tiles are dashed and muted, with the reason under the group, and are not focusable.

Accessibility notes

  • The list view is the keyboard path for everything; the canvas is a picture of it for pointer use. a adds after the selected node, arrows move between rows, Enter edits, Delete removes.
  • Each node has a text name: "c1, Conv2d, output image 32 by 32 by 32, 864 parameters"; a node in error adds "problem: …".
  • The problem count and the summary are a polite status region: each edit announces "2 problems" or "No problems", not every number.
  • Greyed palette tiles are not focusable; their reason is read with the group.
  • Meaning is never colour alone: problems have an icon and words, the memory parts have their names and numbers, the selected node has a thicker outline.
