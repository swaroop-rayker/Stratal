Gate 2 addendum

Asked for by the owner on 2026-11-22: "There is no logistic regression option in classical model creation", then "propose this small fix in the current milestone". SCR-09's Classical mode lists only the estimators that fit the split's task, as approved with the study part (SCR-09hpo_v1.html, frame B: "The estimator list follows the task"). On diabetes, a regression table, logistic_regression and naive_bayes are therefore missing, with no word why, which reads as a missing feature (ML-1.1 names logistic regression). They are offered on breast-cancer and wine.

Checking it found a bug as well. With kmeans selected (or dbscan, hdbscan, pca), turning the study on removes it from the list. The select then shows logistic_regression, while the sentence beside it and the parameter form are still k-means's.

This addendum changes only the estimator select, one line under it, and the study's Turn on button. Everything else keeps its approved and built look, and the layout does not move, so there is no low-fi step. The data are real: diabetes ds_de5f2ad338c9 (regression; train 354, val 44, test 44; 10 columns) and wine ds_6448d354c9c6 (classification, 3 classes; train 142, val 18, test 18; 13 columns). The estimators and their tasks are GET /ml/estimators/schema as it is served today. Open as SCR-09v2-estimators_v1.html#light to start in light.

Decisions to review
  • Every estimator stays in the list, in up to three groups: the split's task first (For regression or For classification), then Any table · ignores the target (kmeans, dbscan, hdbscan, pca), then Not for this split. The last group's options are disabled and say why: "classification only" or "regression only". It stays the native select, so the keyboard, type-ahead and screen readers work as they do now. A disabled option cannot be chosen, so DATA-5.5's "only compatible combinations" still holds.
  • Each option reads name, then title: logistic_regression · Logistic regression, so it can be found by either.
  • A line under the select names what the split rules out, and why, so the answer is there while the list is closed. It is absent when nothing is ruled out.
  • With a study on, the four that ignore the target are disabled with "not in a study", since a study scores each fold against the target (cv_accuracy, cv_r2). While one of them is selected, Turn on is disabled and says why. The list no longer changes under a selection, which fixes the bug above.
  • Unchanged: the default (random_forest), the order inside each group (the schema's), the API, the schemas and every requirement.

Accessibility notes

  • It stays a native <select> with <optgroup label>. A disabled option's reason is part of its text, so a screen reader reads it with the option and announces it as unavailable. The reason is in words, not in the dimming alone.
  • The line under the select is the select's description (aria-describedby), so it is read when the select takes focus.
  • Turn on uses aria-disabled rather than disabled, so it stays in the tab order and reads its reason, which is its description.
  • Contrast: the reasons and the line use the text tokens (--text-muted, --text-secondary), which pass AA on --surface and --surface-raised in both themes. The browser draws the dimmed options of the real list itself; WCAG 1.4.3 exempts inactive controls.
