The figures are illustrative: the question set is not written yet (decision 6: I draft it, the owner checks it), so hit@k, the relevances and the missed questions are invented in plausible ranges, not measured. The questions themselves and the sections they are labelled with are real: each is answered by the named section of Stratal's docs. Index versions as on SCR-03: chunk size 256 (about 970 chunks) and 128 (about 1,920), IDs placeholders.

Layout decisions to review

  1. The report is SCR-06 with a different body: the same header, rebuild action and layout as the phase-1 eval report, so a version's reports look like one family. The kind is in the title ("Retrieval report").
  2. hit@1, hit@5 and hit@10 are three tiles at the top, each as a share and a count; nothing else competes with them.
  3. Other index versions sits directly under the tiles, before the detail, because comparing chunk sizes is the demo's question (Flow 7): one row per index version of the same corpus and question set, this one marked, the best hit@5 in bold.
  4. Relevance and the threshold share one card: on the left the two histograms on one axis (answerable filled, unanswerable hatched, so they are told apart without colour) with the current threshold as a dashed line; on the right the threshold table, 0.30 to 0.80 in steps of 0.05, each row with how many answerable questions would still be answered and how many unanswerable ones would abstain. A row's Use sets it, after a confirmation.
  5. Missed questions are a table at the bottom: the question, its labelled section, the top 3 retrieved instead (section and relevance). Unanswerable questions are not "missed"; they appear only in the relevance chart.
  6. The confirmation says what the threshold does in the counts of this report, and that it applies to every index built with this embedding model.
  7. SCR-14's retrieval section is a form like its others: the threshold for bge-small-en-v1.5 (empty until set, with what that means), the default k, and a link to the report it was chosen from.
