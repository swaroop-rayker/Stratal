Layout and hierarchy only. It replaces the phase-1 drawer (SCR-02-lofi_v1.html frames F and G, built in M6) for the two faults the owner reported: it sent no dataset_type, so a CSV became image–caption pairs, and it listed every registered stage and turned the ticks into until_stage, so unticking one stage unticked every later one. As approved in open point 7: the type first, then only that type's stages in its order, one Stop after choice (until_stage, no API change), transform the only stage with a switch, the stages from GET /dataset-types's new stages, no type guess. The data is real: the folders under sources/, the wine and coco10k versions, and the stages' own fields and defaults from GET /config/schemas/{name}.

Layout decisions to review

  1. The drawer widens from 440 to 480 px (as the Train a model drawer), so each stage row has room for a line on what it does and the Stop after radio on its right.
  2. Order of the body: Start from → Source → Type → Dataset → Stages. The type sits right under the folder, since it is about what the folder holds; nothing under it shows until it is chosen (frame A).
  3. The type is a list of four radio cards, each with what its folder must hold (from the new source field). From a version, one dashed card with the version's type, not changeable (frame C).
  4. The stages are a chain: one row per stage, in the type's order, the stage name, one line on what it does, its key setting, and a Stop after radio on the right. The last stage is chosen by default. Stages after the chosen one read "not run", hatched and dimmed, and keep their settings (frame D). A line above the chain says why there are no checkboxes: "Each stage reads the one before it."
  5. A stage's settings open under its row (▸), generated from its schema, only the fields for this type: ingest on a table shows table.target and table.kinds, not min_size, which is about images (its default is still applied).
  6. transform has a switch in place of the radio. From a folder it is disabled with the reason and a Stop after ingest button (frame B); from a raw table version it is enabled, and switching it on closes the drawer and opens SCR-15 (frame C).
  7. The footer keeps Cancel and Start job, and Start job says how far the run goes: "Start job · to split".

One question this layout depends on

  1. How the table's target is chosen. Ingest needs table.target, a column name, before anything has read the table, so today it is typed, and a typo shows only when the job's ingest fails. I propose a select of the table's columns, read from its header: GET /sources gains columns for a folder that holds one table (one added field; reading a CSV's first line or a Parquet file's schema, not its rows). The same list fills table.kinds. The alternative keeps a text field, with the refusal at ingest.
