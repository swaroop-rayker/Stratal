Layout decisions to review

  1. Columns is the second tab, after Rows, and appears on tabular versions only. The header, lineage strip and tiles stay as approved.
  2. One summary line above the table: columns, features, the target with its task, and the rows counted: "over 178 accepted rows". When rows are not counted it says how many and why, with a link to Rows filtered to them (frame C). On a transformed version, a second line names the operations that made it, with Edit the transform… (frame B).
  3. One table row per column, in the schema's order, sortable by any header; two small filters, Kind and Role. Columns: name, kind, role, encoding, missing, distinct, distribution.
  4. The distribution cell is a 12-bar sparkline for a number, with min · median · max beside it in mono; for a category, its top 5 as short bars with their counts and "+N more". Every sparkline in the table has its own height scale, so a skewed column (frame C) still shows its shape.
  5. Encoding is in words: one_hot · default in grey when not set, the choice in plain text when set, "—" for a number used as a number. An ignored column stays in the table, dimmed, with "ignore", so it can be seen that it is left out.
  6. Missing reads as a count and a share ("0" in grey; "1,204 · 0.6 %" otherwise).
  7. A row expands in place (click, or Enter; j / k move): a 20-bin histogram beside a text table of the same bins (accessibility rule); for a category, every count up to 50; for the target, the class counts or its histogram. A drawer would cover the table being compared.
  8. Big tables load once: the figures are computed from the manifest on first view and cached by version ID, like the Distributions tab; the first view of a large table shows a progress line instead of a spinner (frame D).

One question this layout depends on

  1. Exact distinct counts on large tables? The figures stream through the manifest in batches (rule 31), and an exact distinct count holds every distinct value of a column in memory. For wine and power.parquet that is small (the most is 4,186, Global_active_power), but a column of IDs or timestamps on 2 million rows would hold 2 million values. I propose exact up to 10,000 distinct values, then "more than 10,000", which keeps memory bounded and still tells a code from a measurement. The alternative is always exact.
