Layout decisions to review

  1. Two levels, like datasets: a list of lineages (/models), then one lineage with its versions (/models/:lineage). A lineage is one model on one task (ADR-0015); its versions are its base and its runs.
  2. The versions table answers "which weights do I have, and how good are they": state (base, partial, trained), weights (present, deleted), the dataset version, the main metric, pinned. Filter by state (REG-1.2).
  3. A right-hand column holds what is about disk and retention, beside the versions it acts on: disk use as one stacked bar split base / latest / intermediate / pinned / checkpoints, with the total against the bytes on disk (REG-2.11); the lineage's keep_intermediate; and Preview cleanup, a dry run that lists what would go (REG-2.9).
  4. Deleting is never one click. Running retention, or lowering N, opens a dialog listing the exact versions and sizes (REG-2.10). Base and pinned versions, and versions in use, are marked and never listed for deletion (REG-2.1, REG-2.5, REG-2.8).
  5. A version opens in a drawer with its full resolved config, dataset version, job, parent and metrics (REG-1.1), and the actions that apply to it: Pin, Re-train when its weights are gone (REG-2.7), Try it.
  6. Try it takes a sample input and shows the prediction and the device that served it, because during training it is the CPU (REG-1.4, ADR-0016).
