Decisions to review (beyond the approved low-fi)
  • Chat joins the sidebar under Work, after Models, with a speech-bubble icon and the shortcut g c, like the other entries.
  • Citations and source numbers are the one accented element in an answer: mono numbers in a small accent-soft box. A source's relevance is its number plus a thin bar in text-secondary (not a status colour: relevance is not good or bad by itself), so the eye goes to the cited sources, then to how close they were.
  • The footer is mono 11 px in text-muted, its labels in text-secondary; the route in small capitals. A cold start is the only coloured value, in warning ("cold start 3.4 s"), because it is the one figure that explains a slow answer.
  • An abstention has a dashed border-strong outline on no fill and an info icon; a refusal is the design system's error state (danger at 50 % on danger-soft, an alert icon) inside the answer's shape, with Retry as a secondary button. Neither uses colour alone: both lead with words ("I don't know.", the error code).
  • The GPU line is a warning callout (warning-soft, a pause icon), above the composer, with the job as a link; it is the only warning colour on the page while it shows.
  • Send is the page's only primary button, with a send icon; while an answer streams it becomes a secondary Stop with a square icon, so stopping never looks like the main action. The streaming caret is an accent block that blinks (still under reduced motion).
  • The mode is a three-button group (the design system's pressed state on the chosen one), with an icon each; the version select beside it is the standard select, its options showing dataset, version ID, stage and size.

What does a content hash mean, in one sentence?

A content hash is a fingerprint computed from the data itself, so identical content always gives the same hash and any change gives a different one.

2How are dataset version IDs computed?
3

A version ID is ds_ followed by the first twelve hex characters of a SHA-256 over two hashes: the content hash of the rows and the hash of the config 1. Each row is encoded with its non-null columns in name order and hashed, and the row digests are added together, so row order and file compression do not change the ID 1. Because versions are immutable and stages exchange version IDs, the same parent and config reuse the existing version 2.

Accessibility notes

  • Keyboard path. / focuses the message box from anywhere on the page; Enter sends, Shift+Enter adds a line, Esc stops; Alt+1–3 pick the mode. Tab order: conversations (j / k inside the list), the conversation's answers, each answer's citations and sources, then the composer. A citation link moves focus to its source; Enter there opens SCR-03.
  • Announcements. The conversation is a log (role="log", aria-live="polite"), but a streaming answer is announced once it is done, not token by token; "Answer stopped" and a refusal's code are announced when they happen. The GPU line is a polite status.
  • Never colour alone: citations are numbers; an abstention and a refusal lead with words and an icon; the pressed mode is also aria-pressed; a cold start is said in words beside its colour.
  • Contrast uses the text tokens on --surface, --surface-raised and --bg, as approved; accent text in light (citations, source numbers) uses a 90 % mix with text-primary, and warning text in light the 85 % mix, as at earlier Gate 3s. Checked by measurement before review.
  • Motion: the caret blinks with steps, not a fade, and stays solid under prefers-reduced-motion; skeletons stop shimmering.
