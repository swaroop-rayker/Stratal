Layout and hierarchy only, inside the approved SCR-01 shell (faint). Blue numbers are annotations. The slice is what SCREENS.md open point 1 (a) says: the list with state and kind filters, open, cancel and retry. Pause, resume and queue control arrive with phase 2 (M8) and are not drawn.

Layout decisions to review

  1. One table, active jobs pinned on top. Running and queued jobs sit in an "Active" section above "Finished", whatever the sort, because they are the ones you act on. Finished jobs are newest first.
  2. Each row answers "what is it doing or how did it end" in one column: progress for a running job, what it waits for when queued, the error code and reason for a failure, the output version for a completed one.
  3. Row actions are on the row, shown on hover and focus: Cancel for queued or running (with the same confirm as SCR-04), Retry for failed. Opening is a click or Enter anywhere on the row and goes to SCR-04.
  4. Filters are a state button group with counts (the pattern approved with SCR-03), a dataset filter, and a kind filter. In phase 1 every job is a pipeline job, so kind shows only "pipeline" and is disabled; it becomes useful when training and studies arrive.
  5. Live: rows change in place as job messages arrive on the global stream; a new job appears at the top of Active with no reload.
