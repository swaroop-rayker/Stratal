Layout decisions to review

  1. Two ways in. Fine-tune… on a trained version's row and drawer on SCR-11 opens this page with ?init_from=mv_…. On SCR-09 itself, the Start from card becomes a choice: Fresh weights (today's behaviour, the lineage's base) or A trained version, which lists the versions of this model.
  2. With a trained version the architecture is the parent's. The Model card names the parent and locks the spec; Edit in builder is replaced by one sentence saying why (changed layers could not take its weights). Only the head can change, by resetting it.
  3. The Start from card checks compatibility in words, one line per rule against the chosen split: dataset type, input shape, output (classes), and for tables the columns after encoding, for texts the vocabulary. Each line is ✓ or ✗ with both values. Under it, one sentence says where the version will be registered: it joins the parent's lineage, or founds a new one with its parent in another lineage (K9).
  4. Reset head is a toggle shown with every trained version, off by default. When the classes differ it is required: the output line is ✗ and Start run is disabled until it is on. Resetting re-initialises only the locked output node (RUN-1.10.AC3). A different input shape cannot be fixed this way, so it has no toggle: it says a new model is needed.
  5. Freezing is a list of the layers that have weights, in graph order, by node ID, type, output shape and parameters, each with a checkbox and Freeze up to here. A total says how many parameters will train. A frozen BatchNorm also keeps its running statistics (it stays in eval mode, K9), and the list says so once. The head cannot be frozen while it is being reset; freezing every layer is refused ("nothing would train").
  6. The training form is prefilled from the parent's run and marked as such, as Start again with N does (SCR-09 v1, frame C). Nothing is changed for you; one hint under learning_rate says fine-tuning often uses a smaller one. The optimizer and schedule start fresh (K9).
  7. The VRAM check counts gradients and optimizer state for trainable parameters only, so freezing lowers it. The builder's estimate gains that input (ADR-0017 rule 7, recorded in the RUN-1.10 addendum).
  8. "What will happen" names the epoch-0 check: one validation pass before step 1, logged as epoch 0, and on the parent's own split it should equal the parent's val loss (RUN-1.10.AC1). It also says the parent is now protected from retention while this version keeps its weights (REG-2.8).
  9. Refusals on the Start from card, not as toasts: a version whose weights were deleted (with Re-train, REG-2.7), an input shape mismatch, a text vocabulary mismatch, and a classical model (classical models always start fresh). The server's refusal before the run lands on the same card, naming the mismatch (AC3).
  10. In a study, init_from and the freeze list are fixed for every trial: the search space shows them as one locked row, and they have no Tune toggle (K9).
