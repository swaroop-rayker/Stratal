SCR-04 v2 — Live job view, training runs · hi-fi mockup v1

Gate 2, step 2 of 2

Built on the approved low-fi wireframe (SCR-04v2-lofi_v1.html, approved 2026-11-17) and the approved SCR-04 v1 hi-fi, inside the SCR-01 shell, using only design system v1 tokens and components. Charts are static SVG here; the real screen uses ECharts with the same tokens. Open as SCR-04v2_v1.html#light to start in light. The data: job_0031, a small CNN on the CIFAR-10 split, epoch 7 of 20.

Decisions made in this step, for review
  • Train and validation series use data-viz categorical 1 and 2 (blue and orange): train as a line per step, validation as dots per epoch joined by a dashed line. Each chart names its series in a key, so colour is never the only cue.
  • Epoch segments reuse the timeline bar's look with job-state colours: completed green, running blue with a thicker edge, pending dashed. The checkpoint diamond is drawn in text colours, filled for the one kept, so it reads in both themes without a new colour.
  • State banners reuse the activity card's shape with the job-state colour of their state: paused amber, stalled pink. They replace the activity line, as the failure panel does in v1.
  • Pause is a secondary button beside Cancel (danger); Resume is the primary button when paused. The out-of-memory panel's primary action is Start again with 128.
  • New icons: none. Pause, play, alert, clock and refresh are already in the set.
  • Proposed design-system extension (needs approval): checking this mockup found two light-theme contrast failures that the built app has too. The error badge (danger on its soft tint) measures 3.86:1, and the failure panel's muted labels 4.48:1; every screen's error state shows such a badge. Proposed: in light, a semantic badge's text gets the 80 % mix toward text-primary already approved for pills, and labels on a tinted panel use text-secondary, as on tinted log rows. Then 5.03:1 and 6.19:1. If approved, the built app gets the same two rules in M8.

Accessibility notes for implementation

  • Every chart has a table view with the same numbers; train and validation are named in each chart's key, never colour alone.
  • The epoch timeline is a list; each epoch is announced with its state and whether its checkpoint is kept.
  • Banners are role="status" and announced once when the state changes; the out-of-memory panel is role="alert".
  • Pause, Resume and Cancel are reachable by keyboard in that order; Cancel keeps v1's confirm dialog.
