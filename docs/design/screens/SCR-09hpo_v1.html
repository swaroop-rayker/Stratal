Gate 2, step 2 of 2

Built on the approved low-fi wireframe (SCR-09hpo-lofi_v1.html, approved 2026-11-19) and on SCR-09's approved hi-fi mockup and Gate 3 build, using only design system v1 tokens, components and patterns, with no new icon. Everything SCR-09 already has keeps its approved look; this mockup draws what M10 adds. The data are two set-ups. The first tunes the Small CNN on CIFAR-10 (ds_f8e67211dd94): the learning rate, the batch size (64, 128, 256 or 2048) and the weight decay. The second tunes a random forest on breast cancer (ds_2b7e04a91c55). Open as SCR-09hpo_v1.html#light to start in light.

Decisions made in this step, for review
  • The tune toggle is a small button at the right of each field's label, with the sliders icon and the word Tune. It's pressed (accent) when on. A tuned field's input gets an accent border and becomes a range (low, high and a scale select) or choice chips. The helper below it gives the field's own range, which the study's range must stay inside.
  • The study card is where the old collapsed section was, now open. On the left is the search space, as a compact table with one row per marker. On the right are the limits, the objective, pruning and the seed, in the schema-form pattern, two to a row.
  • The right-hand column keeps its approved shape. The VRAM check says worst case in the space. Then come a plan paragraph and Start study as the page's one primary button. When the worst case is over the cap, the warning callout offers Drop 2048 from batch_size, with Start anyway beside it, as SCR-09 frame B does for one run.
  • Network and Classical are a segmented control in the Model card's header, the control the Device card uses. In Classical, the estimator is a select, and its parameters are a generated form with the same tune toggles.
  • The data card names the task as a badge: classification or regression.
  • A refused marker shows the danger colour and an alert icon on its own row of the space table, and on the field if it is visible. A cross-field rule shows on its field before anything is sent, as SCR-09's field errors do.
  • The duration estimate includes S-09's start cost: 20 trials of about 65 s, plus about 19 s each, make about 28 min.

Folds come from the train split, grouped so that duplicates never sit on both sides of a fold (ADR-0018 rule 4). Median pruning is on, from fold 1. The validation split scores the best configuration once it is refit; it is not used for tuning.

Where it runs

On the CPU queue, with every trial in one job (a trial takes seconds here; S-09). There is no device choice and no VRAM check for classical models.
Up to 50 trials or 10 min. The best configuration is refit on the train split, scored on validation, registered, then tested once.

With the study turned off, the same card trains one random forest with the values set (ML-1.1), and the button reads Start run. The estimator list follows the task. For regression it offers linear, ridge, lasso and the regressor forms of the others. For any table it also offers kmeans, dbscan, hdbscan and pca, which ignore the target.

Accessibility notes

  • Tune is a toggle button (aria-pressed) named with its field ("Tune learning_rate"). Turning it on moves focus to the range's first input.
  • A range's two inputs are labelled "learning_rate, low" and "learning_rate, high". The field's own range is their description, and a refusal replaces it, with aria-invalid.
  • Each space row's remove button is named "Stop tuning field". Removing a row returns focus to the field's Tune button.
  • The worst-case warning is a polite status with an icon and words. The bar is hidden from screen readers, since the table beside it says the same.
  • Ctrl+Enter starts the study, as it starts a run.
