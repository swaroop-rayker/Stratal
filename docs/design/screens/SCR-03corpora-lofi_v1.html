Layout and hierarchy only, inside the approved SCR-03: its header, lineage strip, tiles, tabs and row drawer are reused, faint where unchanged. Blue numbers are annotations. The corpus is Stratal's documentation as decision 5 defines it, the 36 Markdown files of docs/, docs/decisions/ and docs/spikes/ without MILESTONES and KICKOFF (752,552 characters); the documents, titles, sizes and the seven .json files under docs/spikes/ are real. The chunk counts are estimates from the sections and their word counts (about 970 chunks at 256 tokens, 1,920 at 128), since chunk is not built; version IDs are placeholders (ds_…). The instruction pair in frame D is written for the mockup: there is no instruction-pairs source yet.

Layout decisions to review

  1. SCR-03 stays one screen for every stage; what changes by stage is the Rows tab's columns and the tiles (SCREENS v5's table). No tab is added for corpora; Columns, Models and the train and transform actions are hidden, as they are for images.
  2. The lineage strip says what each corpus stage did in one fact: "36 documents" → "35 kept" → "≈ 970 chunks · 256 tokens" → "≈ 970 vectors · bge-small"; the open version outlined.
  3. An index version's tiles are chunks, documents, vectors, dimension, the index's size on disk, and the embedding model with its revision. Its two actions lead the header: Ask this index (to SCR-12, RAG, this version) and Build the retrieval report (to SCR-06).
  4. A chunk row is: chunk key, document, section path, tokens, the text's first line. The table filters by document (a select) and searches the text (/). Rows are virtualised.
  5. The row drawer shows the whole chunk, with the part it shares with the previous chunk (the overlap) shaded and labelled, its offsets in the document, its tokens, and Previous chunk / Next chunk. Opened from a citation (?row=), it opens at once and says "Cited as [1] in a chat answer" with a link back.
  6. A documents version (ingest, clean_text) lists files: path, title (the first heading), characters, status and reason. Non-text files are kept as rejected · unsupported_format, as for any type.
  7. The Start pipeline drawer gains two type cards, Text corpus and Instruction pairs, each with what its folder holds; the chosen type's stages follow the approved chain (one Stop after). chunk's three fields are shown; index's embedding model is read-only text.
  8. An instruction pair's row drawer shows instruction, input and output, then the chat format the pairs' adapter makes (ADR-0022 rule 2), so the owner can check what M13's fine-tuning will see.
