SCR-14 — Settings · hi-fi mockup v1

Gate 2, step 2 of 2

Built on the approved low-fi wireframe (SCR-14-lofi_v1.html, approved 2026-11-17) inside the SCR-01 shell, using only design system v1 tokens, components and patterns, plus one proposed icon. Values are the accepted defaults (OC-3) and the three lineages of SCR-11. Open as SCR-14_v1.html#light to start in light.

Decisions made in this step, for review
  • Fields follow the design system's schema-form pattern (UI-2.3): the label is the property name in mono with its type as a badge; the schema's description, range and default are the helper text below the input; an error from the API replaces the helper. The low-fi's plain-English label is now the start of the helper. One field per row, not the pattern's two columns, because each field has its "applies" note and live context beside it.
  • When a field applies is a neutral badge beside it: applies at once or new jobs only, from a schema extension x-applies.
  • A changed value gets an info badge changed and a Reset to 300 button; the save bar names each change as old → new. The index shows the number of unsaved changes as a count, not a coloured dot.
  • One new icon is proposed: sliders, for Settings, which joins the sidebar's foot above Theme (SCR-01). No icon in the set says "settings".
  • The thermal context uses the temperature resource colour as a small square, as the status bar does; the numbers carry the meaning.
  • The global deletion dialog is SCR-11's dialog with a lineage column, and asks for delete 2 versions to be typed, as approved in the low-fi.

Accessibility notes for implementation

  • Each input is labelled by its property name; the helper (or the error that replaces it) is its description, and an invalid field has aria-invalid.
  • The unsaved-change count in the index has a text name ("1 unsaved change"), not only the number.
  • The live temperature does not announce itself (aria-live="off"); it updates every second and would drown out the form.
  • The save bar is a status region; the save's toast is polite, the conflict toast is an alert.
  • The deletion dialog focuses "Keep them"; the delete button is disabled, and says why, until the phrase matches.
  • Leaving the page with unsaved changes asks first.
